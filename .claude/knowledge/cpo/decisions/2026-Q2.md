# CPO 判断記録 2026-Q2

## 2026-04-25 — PR #20/スキル設計パターン — レビュー指摘から3原則を設計思想に昇格

### 対象

PR #20 のレビューコメント（reviewer + CodeRabbit）から抽出したスキル設計パターン。

### 判断

以下3点をスキル設計原則として `docs/design-philosophy.md` に追記する（MUST/SHOULD）。

#### 1. git 操作のスコープ一貫性（MUST）

`git status` の検知スコープと `git add` のスコープを一致させること。

- CodeRabbit 指摘（PR #20, id:2964387129）: `review-to-rules` 実行後の変更検知が `git status --porcelain`（全体）で、`git add` が `.claude/rules/ .claude/knowledge/` に絞られている不整合を発見
- 不一致だと「検知はするが追加されない」変更が生じ、後続ステップが不正な前提で進む
- MVV バリュー「フローを切らない」— 不整合による意図せぬ失敗はフローを中断させる

#### 2. ベースブランチ名のハードコード禁止（MUST）

スキル内で `git checkout main` を禁止し、`{baseRefName}` 等で動的取得すること。

- PR #20 の修正コミット（05dd4969）で `git checkout main` → `git checkout {baseRefName}` に修正
- CodeRabbit が承認（id:2964378473）: `develop`, `staging` 等のベースブランチでも正しく動作するようになった
- MVV バリュー「道具に縛られない」— 特定のブランチ名戦略に縛られるスキルは汎用性を損なう

#### 3. グローバルスキル依存のフォールバック明示（SHOULD）

スキルが他のグローバルスキルに依存する場合、利用不可時のフォールバック手順を SKILL.md に明記すること。

- PR #20 の対応（id:2964377599）: `/commit` はグローバルスキル定義済みだが、直接 `git commit` のフォールバックも追記
- CodeRabbit が承認（id:2964379270）: 「スキルが利用できない場合でも安全に動作する」と評価
- MVV バリュー「一発で整う」— スキル依存が原因で動かない状況は初期体験を損なう

### なぜそう判断したか

いずれも一過性の実装修正にとどまらず、**同種のスキル（SKILL.md）を新規作成・更新するたびに適用すべき汎用ルール**であるため、design-philosophy.md のスキル設計原則セクションに昇格させた。

特にスコープ一貫性とブランチ名動的取得は、CodeRabbit が繰り返し指摘する類のバグの根本原因であり、原則として明文化することで再発を防ぐ。

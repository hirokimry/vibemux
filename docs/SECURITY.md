# vibemux セキュリティポリシー

> このドキュメントはプロジェクトのセキュリティ方針を定義する Source of Truth です。

## セキュリティ方針

vibemux はユーザーのシェル環境で動作する tmux セッションランチャーであり、外部通信やデータ永続化は行わない。セキュリティの焦点はリポジトリへの機密情報混入防止とシェル環境の安全性にある。

## 脆弱性報告

セキュリティ上の脆弱性を発見した場合は、GitHub Issues で報告してください。

## 多層防御の実装

### レイヤー 1: pre-commit フック (`.githooks/pre-commit`)

コミット時に staged ファイルを対象に以下を検査する:

| チェック | 内容 |
|---------|------|
| シークレット検知 | AWS キー、API キー、トークン、秘密鍵等のパターンマッチ |
| メールアドレス検知 | `noreply@` 以外のメールアドレスを警告 |
| .env ファイル防止 | `.env*` ファイルのステージングをブロック |
| 大容量ファイル検知 | 1MB 超のファイルをブロック |
| shellcheck | ステージされたシェルスクリプトの静的解析 |
| コミッターメール | `git user.email` が `noreply` を含むことを確認 |

### レイヤー 2: pre-push フック (`.githooks/pre-push`)

プッシュ時にプッシュ範囲の差分を対象に以下を検査する:

| チェック | 内容 |
|---------|------|
| シークレット検知 | pre-commit と同一パターンで差分全体を再検査 |
| メールアドレス検知 | 差分全体を対象に再検査 |
| .env ファイル防止 | プッシュ範囲に含まれる `.env*` をブロック |
| 大容量ファイル検知 | プッシュ範囲の全ファイルを検査 |
| shellcheck | `vibemux`, `.githooks/*`, `**/*.sh` を全て検査 |
| 必須ファイル確認 | `LICENSE`, `README.md` の存在を確認 |

### レイヤー 3: GitHub 設定

- branch protection: main への直接 push 禁止、PR 必須、CI 必須
- GitHub Actions CI: `make check` (shellcheck + テスト) を全 PR で実行

## 既知のリスクと緩和策

### 設定ファイルの `source` 読み込み

`vibemux:15-18` で `~/.config/vibemux/config` を `source` で読み込んでいる。任意コード実行のリスクがあるが、以下の前提で緩和している:

- 設定ファイルはユーザー自身が作成・管理する（他者が書き込み可能なパスは使わない）
- ファイルが存在しない場合はスキップ
- 内容は変数代入のみを想定（関数定義やコマンド実行は非推奨）

### 環境変数経由のコマンド実行

`VIBEMUX_PANE_*` の値は `tmux send-keys` で各ペインに送信される。環境変数に悪意ある値が設定された場合、そのコマンドが実行される。ユーザー自身が設定する前提のため、外部からの注入経路がない限りリスクは限定的。

## データ保護

### 機密情報の取り扱い

- シークレット・APIキー・パスワードをリポジトリにコミットしない
- 環境変数またはシークレットマネージャーで管理する

### 個人情報

- `git user.email` は `noreply.github.com` アドレスを使用する
- コード内に個人メールアドレスを含めない

# CPO 判断記録

プロダクトに関する判断とその根拠を記録する。CPO エージェントがレビュー時に追記する。

## 記録フォーマット

```markdown
### YYYY-MM-DD: 判断タイトル

- **判断**: 何をどう判断したか
- **根拠**: なぜそう判断したか（MVV・原則のどれに基づくか）
- **代替案**: 検討した他の選択肢（あれば）
```

## 判断ログ

### 2026-04-24: MVV Value #2 の改訂原則を確立

- **判断**: MVV Values の副文は「手段の列挙」ではなく「守るべき体験」を記述する原則を採用
- **根拠**: Value #2 の旧副文「ウィンドウ切り替えゼロ。ファイル・git・AIが常に視界にある」は、yazi デフォルト廃止（#32）で「ファイル」が崩壊した。具体物（ファイル・git・AI）を列挙すると、実装変更で Value 自体が陳腐化する。Toyota「現地現物」のように時代不変かつ判定可能な粒度が正解。AI エージェントが Value を判断基準として使う前提では、抽象的すぎると判定不能になり致命的。かつ具体的すぎても時代変化で崩れる。「体験原則」が最適粒度
- **代替案**: (A) 具体物の差し替え「git・AI・実行結果」→ 同じ轍を踏む, (B) 完全抽象化「コンテキストスイッチを発生させない」→ エージェントが判定不能

### 2026-04-18: 言語方針を日本語前面に統一

- **判断**: README.md を日本語版に差し替え、英語版は `README.en.md` として参考情報のみ保持。CLAUDE.md の言語ルールを「応答・ドキュメント・PR 本文・Issue は日本語、コミットメッセージのみ英語、コード内識別子・コメントは英語」に改訂し、エージェント・スキル定義に残る「PR 本文は英語」の規定を撤廃する
- **根拠**: vibemux のターゲットは当面、日本人バイブコーダーであり、記事・コミュニティ発信も日本語前提。MVV.md・docs・コミュニケーションが英日でねじれた状態は、書き手とエージェント双方の認知負荷を増やし MVV の浸透を阻害する。英語圏展開は日本での定着後に着手する段階的方針とし、それまでは日本語に一本化することで一貫性を担保する
- **代替案**: (A) 完全英語化 → 日本人ユーザー向けの説明力が落ち、ターゲット市場と乖離, (B) 英日完全並記 → 二重メンテのコストが Issue/PR/agent prompt の全レイヤーに波及し継続不可能

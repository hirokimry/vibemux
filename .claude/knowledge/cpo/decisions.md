# CPO 判断記録

プロダクトに関する判断とその根拠を記録する。CPO エージェントがレビュー時に追記する。

## 記録フォーマット

```markdown
### YYYY-MM-DD: 判断タイトル

- **判断**: 何をどう判断したか
- **根拠**: なぜそう判断したか（MVV・原則のどれに基づくか）
- **代替案**: 検討した他の選択肢（あれば）
```

## 判断ログ

### 2026-04-24: MVV Value #2 の改訂原則を確立

- **判断**: MVV Values の副文は「手段の列挙」ではなく「守るべき体験」を記述する原則を採用
- **根拠**: Value #2 の旧副文「ウィンドウ切り替えゼロ。ファイル・git・AIが常に視界にある」は、yazi デフォルト廃止（#32）で「ファイル」が崩壊した。具体物（ファイル・git・AI）を列挙すると、実装変更で Value 自体が陳腐化する。Toyota「現地現物」のように時代不変かつ判定可能な粒度が正解。AI エージェントが Value を判断基準として使う前提では、抽象的すぎると判定不能になり致命的。かつ具体的すぎても時代変化で崩れる。「体験原則」が最適粒度
- **代替案**: (A) 具体物の差し替え「git・AI・実行結果」→ 同じ轍を踏む, (B) 完全抽象化「コンテキストスイッチを発生させない」→ エージェントが判定不能

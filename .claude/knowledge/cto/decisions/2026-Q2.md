#### 変更検知: `git status --porcelain` vs `git diff --quiet HEAD`

#### ベースブランチの参照

- スキル内でブランチをチェックアウトする際は `git checkout main` のようなハードコードを避け、`git checkout {baseRefName}` を使う

#### グローバルスキルのフォールバック

- スキル内でグローバルスキル（`/commit` 等）を呼び出す場合、利用できない環境に備えて直接コマンドの手順をフォールバックとして併記する

#### CodeRabbit 未解決コメント判定

- `in_reply_to_id == null` の CodeRabbit コメントが「未解決のトップレベルコメント」
- 返信済みID（`in_reply_to_id` が一致するコメント群）との差分を `jq --argjson` で算出する 2 ステップ実装
- `review-to-rules` スキルと同じ判定ロジックを `pr-merge-loop` でも共用する方針

## 2026-04-25 — PR #27, #43 技術知見 — `.claude/` 配下のベンダーファイル管理

### 対象
PR #27: `.claude/hooks/protect-branch.sh`, `sync-gate.sh`, `team-auto-approve.sh`, `agents/plan-legal.md` への指摘
PR #43: `.claude/agents/ciso.md`, `.claude/skills/session-harvest/SKILL.md` への指摘

### 知見

#### `.claude/` 配下のベンダーファイル

以下のファイルは `vibecorp install.sh --update` によって自動生成・上書きされる：

- `.claude/hooks/` 配下の全ファイル
- vibecorp plugin 由来の `.claude/agents/` ファイル（例: `ciso.md`, `plan-legal.md`）
- vibecorp plugin 由来の `.claude/skills/` ファイル（例: `session-harvest/SKILL.md`）

直接修正しても次回 `install.sh --update` で上書きされる。バグ・改善は vibecorp upstream リポジトリで修正する。

**独自追加ファイルは対象外**: プロジェクト独自で追加した `.claude/agents/security-reviewer.md`, `.claude/agents/docs-reviewer.md` 等はこの制約を受けない。

#### `.claude/lib/` の untracked 管理

- `.claude/lib/common.sh`（および `.claude/lib/` 全体）は `install.sh --update` のランタイム配布ファイル
- `.claude/.gitignore` の `lib/` エントリで意図的に untracked 管理
- git tree に存在しなくても誤検知ではない。`install.sh --update` 実行後の環境では正常に存在する
- `sync-gate.sh`, `review-gate.sh` 等がこのファイルを source しても正常動作する

## 2026-04-25 — check_command ヘルパー追加 — 起動時コマンド存在チェックの設計判断

### 対象

vibemux スクリプトへの `check_command()` ヘルパー関数追加

### 判断内容

#### check_command() の設計

`VIBEMUX_PANE_LEFT` / `VIBEMUX_PANE_RIGHT` に設定されたコマンドの存在チェックを実行時（`cmd_new()` 呼び出し時）に行う。

```bash
check_command() {
  local label="$1" cmd="$2"
  local bin="${cmd%% *}"
  [[ -z "$bin" ]] && return 0
  command -v "$bin" >/dev/null 2>&1 || die "command not found: $bin (set by $label)"
}
```

#### 設計上の判断

- `${cmd%% *}` でコマンド文字列の先頭トークン（バイナリ名）のみを抽出する。オプションや引数を含む値でも正しく判定できる
- 空文字列の場合は早期 return でスキップ。未設定の環境変数が空になってもエラーにならない
- `command -v` を使用。`which` より POSIX 準拠で環境依存が少ない
- エラーメッセージに `$label`（環境変数名）を含めることで、どの設定値が原因かをユーザーが特定しやすい
- 設定ミスを起動直後に die することで、セッション途中での無音失敗を防ぐ

#### テスト

テスト5件を `tests/` 配下に追加（正常系・空コマンド・コマンド不在・各ペイン変数ごと）。
